# Smart Attendance & Field Activity Monitoring System

AI-enabled attendance and field-activity monitoring for rural development field workers (Chengalpattu District, Tamil Nadu). It's a Flutter Android app running on **Firebase Authentication**, **Cloud Firestore** and, optionally, **Cloud Storage**, so there's no separate backend server to deploy.

> ⚠️ **Build status: NOT yet compiled, NOT device-tested, security rules NOT yet run against the emulator.** The development environment couldn't run Flutter, Gradle or the Firebase emulator. See [`docs/STATUS.md`](docs/STATUS.md) for exactly what is verified and what isn't.

**Start here**
1. [`docs/SECURITY_SETUP.md`](docs/SECURITY_SETUP.md): put your admin Gmail into `firestore.rules` and publish the rules. **Do this first.**
2. [`docs/GITHUB_UPLOAD_AND_BUILD.md`](docs/GITHUB_UPLOAD_AND_BUILD.md): beginner guide to uploading to GitHub, adding secrets and downloading the APK.
3. [`docs/SIGNING_KEY.md`](docs/SIGNING_KEY.md): keep your signing key safe.
4. [`docs/STORAGE.md`](docs/STORAGE.md): photo evidence storage and the **Blaze billing requirement**.
5. [`CHANGES.md`](CHANGES.md): what changed in this revision.

> **Synthetic data notice.** No official worker records, employee IDs or GIS boundaries were available. Demo data is generated by the app and labelled **SYNTHETIC DEMO** (Product Report §5.4, §9). Official data can be entered through *Workers → Add/Edit* and *GIS boundaries → Import GeoJSON*.

## Technology stack
| Layer | Choice |
|---|---|
| Frontend | Flutter 3.27.4 (Dart 3.6), Material 3, Android only |
| Authentication | Firebase Auth: Google Sign-In, email/password, registration, password reset |
| Database | Cloud Firestore with server-enforced security rules (`firestore.rules`) |
| File storage | Cloud Storage for Firebase for evidence photos (**Blaze plan**; off by default) |
| Maps / GIS | OpenStreetMap tiles via `flutter_map`; on-device point-in-polygon, distance to edge |
| GPS | `geolocator` (accuracy, timestamp, mock-location flag) |
| Face verification | ML Kit face detection plus MobileFaceNet TFLite (pinned, SHA-256 verified; see `third_party/mobilefacenet/MODEL_CARD.md`) |
| Build | Gradle 8.10.2 (official wrapper, validated in CI), AGP 8.7.3, Kotlin 2.1.0, Java 17 |
| CI | GitHub Actions: rules tests on emulators, `flutter analyze` (warnings fail), unit tests, signed release APK |

## Modules (Product Report §5)
| § | Module | Implementation |
|---|---|---|
| 5.1 | Auth & users | Google and email login, registration, reset, logout. New accounts are `pending_approval` until staff approve them. Initial Admin comes only from an allow-listed, verified email |
| 5.2 | Worker management | Search/filter/create/edit; employee ID (human-facing) vs database ID; supervisor and boundary assignment |
| 5.3 | Face verification | 2-sample enrolment with consent. Template stored in owner-only `face_templates/{uid}`. On-device verification returns `worker_id, verified, similarity, status, message, timestamp`, with unavailable / not-enrolled / no-face states |
| 5.4 | GPS & GIS | Live GPS with accuracy, inside/outside check, edge-uncertainty flag, boundary attributes, foreground live tracking, draw/import boundaries |
| 5.5 | Attendance | Check-in/out linked to face and location outcomes; present, late, pending verification, rejected, absent; supervisor override with note |
| 5.6 | Tasks & activities | Assign tasks; status flow; activity reports with GPS and up to 3 photos (Storage); approve/reject |
| 5.7 | Alerts | 7 configurable rules with severity/status, resolution notes and live in-app banners |
| 5.8 | Dashboard & analytics | Live KPIs, charts, map, filters; reports with CSV export |
| 11 | Security | Least-privilege rules, biometric isolation, consent, append-only audit log |

## Roles
| Role | Access |
|---|---|
| Field Worker | Own attendance, tasks, activities, alerts, profile |
| Supervisor | Dashboard, map, workers (no role changes), tasks, reviews, alerts, boundaries, reports, audit |
| Administrator | Everything, plus roles, settings, demo data, biometric deletion |
| Auditor | Read-only dashboard, map, reports, audit |

## Building locally (optional)
```bash
flutter pub get
sha256sum -c assets/models/mobilefacenet.sha256
cp android/key.properties.example android/key.properties   # fill in; put release.jks in android/app/
flutter analyze --no-fatal-infos && flutter test
flutter build apk --release
```
